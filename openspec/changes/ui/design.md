## 概述
为汽车座舱中控屏开发纯前端页面：16:9 横屏布局，左侧竖向信息卡片区（可翻页切换），右侧宽屏地图展示区（静态占位/Mock，不接真实地图服务）。技术栈 React，支持跟随系统的日/夜双主题。仓库当前为空（仅 README），按全新工程从零搭建。

## 要点
- 布局：根容器锁定 16:9 宽高比，横向分栏——左栏窄（竖向信息卡片），右栏宽（地图占位）。
- 左侧卡片：车辆状态（车速/电量/续航）、空调与温度控制、音乐/媒体播放、时间/天气；卡片支持翻页/切换，带分页指示。
- 右侧地图：静态占位图/Mock 展示，预留后续接入真实地图的容器与接口位。
- 主题：日/夜双主题，默认跟随系统 `prefers-color-scheme`，通过 CSS 变量统一切换。
- 纯前端：无后端、无真实网络请求，所有数据用本地 Mock。
- 触控：卡片翻页交互面向触屏操作设计（**点击与滑动两种手势均需支持**）。
- 可读性：日/夜主题下所有卡片与地图占位内容均需清晰可读，集成阶段以可量化手段（对比度阈值 WCAG AA / 日夜双主题截图对比）客观校验。

## 影响范围
全新前端工程：新增构建配置（Vite + React）、入口文件、布局壳、主题系统、四类信息卡片组件、卡片翻页容器、地图占位面板、页面集成装配。脚手架还会引入常规静态资源（favicon、public/ 静态目录等），不涉及既有模块改造，README 保持不动。

## 拆分说明
工程脚手架（含 App 布局壳）为基础任务；主题系统、卡片容器、各卡片组件、地图面板各自独立目录互不相交；最后一个集成任务改写 App.jsx 装配全部组件，与脚手架任务共享 App.jsx 故以 deps 声明依赖。

## 本轮复核修订
- 集成任务 AC 补充可量化可读性判定：日/夜两套主题下对关键文本执行对比度检查（≥ WCAG AA 4.5:1），并留存日夜双主题整页截图对比，作为「所有卡片与地图占位内容清晰可读」的客观证据。
- 翻页容器的「切换过渡动画」明确为 nice-to-have（required=false），不构成阻塞；避免与需求 2 的 must-have 混淆。
- 翻页容器 AC 显式拆出「滑动手势翻页」与「点击翻页」两条验证项，确保需求 2「点击或滑动」不遗漏。
- 脚手架任务 touched_files 显式补入 favicon 与 public/ 常规静态资源，减少实施期意外产物。
